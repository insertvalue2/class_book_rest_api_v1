19장. 리프레시 토큰이란?

1. 리프레시 토큰의 개념

1.1 액세스 토큰 만료 시간의 딜레마

12장부터 써 온 JWT는 요청마다 실어 보내서 요청을 누가 보냈는지 증명하는 토큰입니다. 이 장부터는 이 토큰을 액세스 토큰(access token)이라고 부릅니다. 14장에서 만든 인증 필터는 토큰의 서명과 만료 시간만 확인하고 DB를 조회하지 않습니다. 그래서 서버는 이미 발급한 액세스 토큰을 중간에 무효로 만들 수 없습니다. 18장 5.3에서 역할을 바꿔도 기존 토큰에 바로 반영되지 않았던 것도 같은 이유입니다.

이 성질 때문에 만료 시간을 정하기가 어렵습니다. 만료 시간을 길게 잡으면 사용자가 다시 로그인할 일이 줄어듭니다. 하지만 토큰을 도둑맞으면 공격자도 그만큼 오래 그 토큰을 씁니다. 30분처럼 짧게 잡으면 훔친 토큰을 쓸 수 있는 시간은 줄어듭니다. 대신 사용자는 30분마다 아이디와 비밀번호를 다시 입력해야 합니다.

12장에서 JwtUtil의 만료 시간 설정값은 하루로 정했습니다. 보안으로 보나 편의로 보나 만족스럽지 않은 값입니다. 액세스 토큰 하나만으로는 이 딜레마를 풀 수 없으므로 토큰을 하나 더 둡니다.

1.2 액세스 토큰과 리프레시 토큰 비교

리프레시 토큰(refresh token)은 액세스 토큰이 만료됐을 때 새 액세스 토큰을 받는 데에만 쓰는 토큰입니다. 액세스 토큰의 만료 시간은 짧게, 리프레시 토큰의 만료 시간은 길게 잡습니다. 요청마다 오가는 액세스 토큰은 금방 만료되므로 도둑맞아도 피해가 짧게 끝납니다. 사용자는 리프레시 토큰으로 새 액세스 토큰을 받으면 되므로 로그인을 자주 하지 않아도 됩니다.

리프레시 토큰은 서버 DB에 저장합니다. DB에 있으므로 그 행을 지우면 토큰은 바로 무효가 됩니다. 이 장의 로그아웃이 하는 일이 바로 이 행을 지우는 것입니다.

그림 19-1처럼 클라이언트는 평소에 액세스 토큰만 보냅니다. 401 응답을 받으면 그때 리프레시 토큰으로 /reissue를 호출해 새 토큰 한 쌍을 받습니다.

14장의 인증 필터는 토큰이 없을 때와 만료됐을 때를 구별하지 않습니다. 두 경우 모두 401 "로그인 후 이용해주세요"로 응답합니다. 그래서 클라이언트는 401을 받으면 먼저 재발급을 시도하고, 재발급도 실패하면 로그인 화면으로 보냅니다. 클라이언트가 두 토큰을 어디에 보관하고 언제 재발급을 부를지는 React 연동 과정에서 다룹니다.

2. 리프레시 토큰 저장

2.1 RefreshToken 엔티티

리프레시 토큰은 DB에 저장하므로 엔티티가 필요합니다. 한 행에는 토큰 문자열, 토큰 주인, 만료 시각을 담습니다. 한 회원이 노트북과 휴대폰에서 따로 로그인하면 토큰이 두 개 생깁니다. 토큰 쪽에서 보면 회원과 다대일 관계이므로, 5장의 Board처럼 @ManyToOne과 지연 로딩으로 연결합니다.

인증과 관련된 클래스는 새로 만드는 auth 패키지에 모읍니다.

package com.newtenco.blog.auth;

import com.newtenco.blog.user.User;
import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.FetchType;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.ManyToOne;
import jakarta.persistence.Table;
import lombok.Builder;
import lombok.Getter;
import lombok.NoArgsConstructor;

import java.sql.Timestamp;

@NoArgsConstructor
@Getter
@Entity
@Table(name = "refresh_token_tb")
public class RefreshToken {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Integer id;

    @Column(unique = true, length = 100, nullable = false)
    private String token;

    @ManyToOne(fetch = FetchType.LAZY)
    private User user;

    @Column(nullable = false)
    private Timestamp expiresAt;

    @Builder
    public RefreshToken(String token, User user, Timestamp expiresAt) {
        this.token = token;
        this.user = user;
        this.expiresAt = expiresAt;
    }
}

2.2 UUID 토큰과 만료 시각

리프레시 토큰은 JWT가 아니라 UUID(Universally Unique Identifier)로 만듭니다. UUID는 6b1f0c2e-8d4a-4f3b-9a51-2c7e0d9b4a17처럼 생긴 128비트 식별자입니다. 자바의 UUID.randomUUID()는 이 값을 무작위로 만들기 때문에 다른 사람이 짐작해 맞힐 수 없습니다.

리프레시 토큰 안에는 정보를 담을 필요가 없습니다. 서버가 어차피 DB에서 토큰을 찾아 주인과 만료 시각을 확인하기 때문입니다. 뜻 없는 무작위 문자열이면 충분합니다. 토큰이 새어 나가도 그 안에서 회원 정보를 읽어 낼 수 없다는 장점도 있습니다.

다만 이 책은 리프레시 토큰을 원래 문자열 그대로 DB에 저장합니다. DB 내용이 새어 나가면 공격자는 저장된 토큰을 그대로 /reissue에 보내 새 액세스 토큰을 받을 수 있습니다. 실제 서비스에서는 비밀번호처럼 토큰의 해시값(예: SHA-256)만 저장하고, 요청으로 받은 토큰도 같은 방식으로 해시해서 찾습니다. 토큰은 이미 추측할 수 없는 무작위 값이므로 BCrypt 같은 느린 해시까지는 필요 없습니다. 이 책에서는 흐름에 집중하려고 해시 저장은 구현하지 않습니다.

토큰 발급은 RefreshTokenService가 맡습니다. 로그인 기능과 3절에서 만들 재발급 기능이 이 서비스를 함께 씁니다.

package com.newtenco.blog.auth;

import com.newtenco.blog.user.User;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.sql.Timestamp;
import java.util.UUID;

@RequiredArgsConstructor
@Transactional(readOnly = true)
@Service
public class RefreshTokenService {

    public static final String HEADER = "Refresh-Token";
    public static final long EXPIRATION_TIME = 1000L * 60 * 60 * 24 * 14;

    private final RefreshTokenRepository refreshTokenRepository;

    @Transactional
    public String 발급(User user) {
        RefreshToken refreshToken = RefreshToken.builder()
                .token(UUID.randomUUID().toString())
                .user(user)
                .expiresAt(new Timestamp(System.currentTimeMillis() + EXPIRATION_TIME))
                .build();
        refreshTokenRepository.save(refreshToken);
        return refreshToken.getToken();
    }
}

EXPIRATION_TIME은 밀리초 단위로 14일입니다. 발급할 때 "지금 + 14일"을 Timestamp로 만들어 행에 만료 시각으로 저장합니다. 나중에 만료됐는지 확인할 때는 저장된 시각과 현재 시각만 비교하면 됩니다.

HEADER는 리프레시 토큰을 담을 응답 헤더 이름입니다. 로그인 컨트롤러와 재발급 컨트롤러가 같은 이름을 쓰므로 JwtUtil.HEADER처럼 상수로 두었습니다. 이 서비스를 호출하는 곳은 아직 없으므로 서버를 다시 띄워도 달라지는 것은 없습니다.

이제 로그인에 성공하면 리프레시 토큰도 함께 발급합니다. 액세스 토큰은 12장처럼 Authorization 헤더에 담고, 리프레시 토큰은 Refresh-Token 헤더에 담습니다.

package com.newtenco.blog.user;

import com.newtenco.blog.auth.RefreshTokenService;
import com.newtenco.blog.core.handler.errors.BadRequestException;
import com.newtenco.blog.core.handler.errors.NotFoundException;
import com.newtenco.blog.core.handler.errors.UnauthorizedException;
import com.newtenco.blog.core.util.JwtUtil;
import lombok.RequiredArgsConstructor;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@RequiredArgsConstructor
@Transactional(readOnly = true)
@Service
public class UserService {

    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;
    private final JwtUtil jwtUtil;
    private final RefreshTokenService refreshTokenService;

    @Transactional
    public UserResponse.DTO 회원가입(UserRequest.JoinDTO reqDTO) {
        if (userRepository.existsByUsername(reqDTO.username())) {
            throw new BadRequestException("이미 존재하는 유저네임입니다");
        }
        String encPassword = passwordEncoder.encode(reqDTO.password());
        User savedUser = userRepository.save(reqDTO.toEntity(encPassword));
        return new UserResponse.DTO(savedUser);
    }

    @Transactional
    public UserResponse.LoginDTO 로그인(UserRequest.LoginDTO reqDTO) {
        User user = userRepository.findByUsername(reqDTO.username())
                .orElseThrow(() -> new UnauthorizedException("유저네임 혹은 비밀번호가 일치하지 않습니다"));

        if (!passwordEncoder.matches(reqDTO.password(), user.getPassword())) {
            throw new UnauthorizedException("유저네임 혹은 비밀번호가 일치하지 않습니다");
        }
        String accessToken = jwtUtil.create(user);
        String refreshToken = refreshTokenService.발급(user);
        return new UserResponse.LoginDTO(accessToken, refreshToken, new UserResponse.DTO(user));
    }

    public UserResponse.DTO 내정보(Integer id) {
        User user = userRepository.findById(id)
                .orElseThrow(() -> new NotFoundException("회원을 찾을 수 없습니다"));
        return new UserResponse.DTO(user);
    }

    @Transactional
    public UserResponse.DTO 회원수정(UserRequest.UpdateDTO reqDTO, Integer sessionUserId) {
        User user = userRepository.findById(sessionUserId)
                .orElseThrow(() -> new NotFoundException("회원을 찾을 수 없습니다"));
        String encPassword = reqDTO.isPasswordChange()
                ? passwordEncoder.encode(reqDTO.password())
                : user.getPassword();
        user.update(reqDTO.email(), encPassword);
        return new UserResponse.DTO(user);
    }

    public UserResponse.AvailableDTO 유저네임중복체크(String username) {
        boolean available = !userRepository.existsByUsername(username);
        return new UserResponse.AvailableDTO(available);
    }
}

    @Bean
    public CorsConfigurationSource corsConfigurationSource() {
        CorsConfiguration config = new CorsConfiguration();
        config.setAllowedOrigins(List.of("http://localhost:5173"));
        config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE", "OPTIONS"));
        config.addAllowedHeader("*");
        config.setExposedHeaders(List.of("Authorization", "Refresh-Token"));

        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/**", config);
        return source;
    }

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http.headers(headers -> headers.frameOptions(frame -> frame.sameOrigin()));

        http.cors(cors -> cors.configurationSource(corsConfigurationSource()));

        http.csrf(csrf -> csrf.disable());
        http.formLogin(form -> form.disable());
        http.httpBasic(basic -> basic.disable());

        http.sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS));

        http.addFilterBefore(new JwtAuthorizationFilter(jwtUtil), UsernamePasswordAuthenticationFilter.class);

        http.exceptionHandling(ex -> ex
                .authenticationEntryPoint((req, res, e) -> RespFilter.fail(res, 401, "로그인 후 이용해주세요"))
                .accessDeniedHandler((req, res, e) -> RespFilter.fail(res, 403, "권한이 없습니다")));

        http.authorizeHttpRequests(auth -> auth
                .requestMatchers(HttpMethod.OPTIONS, "/**").permitAll()
                .requestMatchers("/join", "/login", "/check-username").permitAll()
                .requestMatchers("/h2-console/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .requestMatchers(HttpMethod.GET, "/api/boards/**").permitAll()
                .requestMatchers("/api/**").hasAnyRole("USER", "ADMIN")
                .anyRequest().denyAll()
        );

        return http.build();
    }
}

@NoArgsConstructor
@Getter

@Table(name = "refresh_token_tb")

}

3.2 토큰 교체(rotation)

재발급할 때 새 액세스 토큰만 주고 리프레시 토큰은 그대로 둘 수도 있습니다. 그러면 리프레시 토큰 하나를 14일 동안 몇 번이든 쓸 수 있습니다. 이 토큰을 도둑맞으면 공격자는 14일 내내 새 액세스 토큰을 받아 갑니다.

그래서 재발급할 때마다 쓴 리프레시 토큰을 지우고 새 리프레시 토큰을 발급합니다. 이 방식을 토큰 교체(token rotation)라고 합니다. 토큰을 교체하면 리프레시 토큰 하나는 딱 한 번만 쓸 수 있습니다. 공격자가 훔친 토큰을 먼저 쓰면 원래 사용자의 다음 재발급이 실패하고, 사용자는 다시 로그인해야 합니다. 이 책의 코드는 이런 재사용 시도를 따로 감지하지 않습니다. 이미 쓴 토큰이 다시 오면 거절할 뿐입니다.

package com.newtenco.blog.auth;

import com.newtenco.blog.core.handler.errors.UnauthorizedException;
import com.newtenco.blog.core.util.JwtUtil;
import com.newtenco.blog.user.User;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.sql.Timestamp;
import java.util.UUID;

@RequiredArgsConstructor
@Transactional(readOnly = true)
@Service
public class RefreshTokenService {

    public static final String HEADER = "Refresh-Token";
    public static final long EXPIRATION_TIME = 1000L * 60 * 60 * 24 * 14;

    private final RefreshTokenRepository refreshTokenRepository;
    private final JwtUtil jwtUtil;

    @Transactional
    public String 발급(User user) {
        RefreshToken refreshToken = RefreshToken.builder()
                .token(UUID.randomUUID().toString())
                .user(user)
                .expiresAt(new Timestamp(System.currentTimeMillis() + EXPIRATION_TIME))
                .build();
        refreshTokenRepository.save(refreshToken);
        return refreshToken.getToken();
    }

    @Transactional
    public AuthResponse.ReissueDTO 재발급(String token) {
        RefreshToken refreshToken = refreshTokenRepository.findByTokenJoinUser(token)
                .orElseThrow(() -> new UnauthorizedException("다시 로그인해주세요"));
        if (refreshToken.isExpired()) {
            throw new UnauthorizedException("다시 로그인해주세요");
        }
        refreshTokenRepository.delete(refreshToken);

        User user = refreshToken.getUser();
        String newAccessToken = jwtUtil.create(user);
        String newRefreshToken = 발급(user);
        return new AuthResponse.ReissueDTO(newAccessToken, newRefreshToken);
    }
}

@RequiredArgsConstructor

    private final JwtUtil jwtUtil;

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();

    @Bean
    public CorsConfigurationSource corsConfigurationSource() {
        CorsConfiguration config = new CorsConfiguration();

        source.registerCorsConfiguration("/**", config);
        return source;
    }

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http.headers(headers -> headers.frameOptions(frame -> frame.sameOrigin()));

        http.cors(cors -> cors.configurationSource(corsConfigurationSource()));

        http.csrf(csrf -> csrf.disable());
        http.formLogin(form -> form.disable());
        http.httpBasic(basic -> basic.disable());

        http.sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS));

        http.addFilterBefore(new JwtAuthorizationFilter(jwtUtil), UsernamePasswordAuthenticationFilter.class);

        http.exceptionHandling(ex -> ex
                .authenticationEntryPoint((req, res, e) -> RespFilter.fail(res, 401, "로그인 후 이용해주세요"))
                .accessDeniedHandler((req, res, e) -> RespFilter.fail(res, 403, "권한이 없습니다")));

        http.authorizeHttpRequests(auth -> auth
                .requestMatchers(HttpMethod.OPTIONS, "/**").permitAll()
                .requestMatchers("/join", "/login", "/check-username").permitAll()
                .requestMatchers(HttpMethod.POST, "/reissue").permitAll()
                .requestMatchers("/h2-console/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .requestMatchers(HttpMethod.GET, "/api/boards/**").permitAll()
                .requestMatchers("/api/**").hasAnyRole("USER", "ADMIN")
                .anyRequest().denyAll()
        );

        return http.build();
    }

본문을 {"refreshToken": ""}로 보내면 @NotBlank 검사에 걸려 400 응답과 "리프레시 토큰이 필요합니다" 메시지가 옵니다.

같은 401이라도 msg가 다릅니다. "로그인 후 이용해주세요"는 필터 단계에서 주소 규칙에 막혔다는 뜻입니다. "다시 로그인해주세요"는 컨트롤러까지 들어갔다가 서비스가 토큰을 거절했다는 뜻입니다.

규칙은 HttpMethod.POST로 좁혀 열었습니다. 재발급은 POST로만 받으므로 다른 메서드까지 열어 둘 이유가 없습니다. /reissue를 /api/** 아래에 두지 않은 데도 이유가 있습니다. /api/**는 역할이 있어야 들어가는 영역인데, 재발급 요청에는 역할을 증명할 액세스 토큰이 없습니다.

4. 로그아웃

4.1 리프레시 토큰 폐기

토큰 방식에서 로그아웃은 서버가 기억하는 것을 지우는 일입니다. 서버가 기억하는 것은 리프레시 토큰뿐이므로, 로그아웃 요청으로 받은 리프레시 토큰의 행을 지웁니다. 행이 없어지면 그 토큰으로는 더 이상 재발급을 받을 수 없습니다.

public interface RefreshTokenRepository extends JpaRepository<RefreshToken, Integer> {

package com.newtenco.blog.auth;

import com.newtenco.blog.core.handler.errors.UnauthorizedException;
import com.newtenco.blog.core.util.JwtUtil;
import com.newtenco.blog.user.User;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.sql.Timestamp;
import java.util.UUID;

@RequiredArgsConstructor
@Transactional(readOnly = true)
@Service
public class RefreshTokenService {

    public static final String HEADER = "Refresh-Token";
    public static final long EXPIRATION_TIME = 1000L * 60 * 60 * 24 * 14;

    private final RefreshTokenRepository refreshTokenRepository;
    private final JwtUtil jwtUtil;

    @Transactional
    public String 발급(User user) {
        RefreshToken refreshToken = RefreshToken.builder()
                .token(UUID.randomUUID().toString())
                .user(user)
                .expiresAt(new Timestamp(System.currentTimeMillis() + EXPIRATION_TIME))
                .build();
        refreshTokenRepository.save(refreshToken);
        return refreshToken.getToken();
    }

    @Transactional
    public AuthResponse.ReissueDTO 재발급(String token) {
        RefreshToken refreshToken = refreshTokenRepository.findByTokenJoinUser(token)
                .orElseThrow(() -> new UnauthorizedException("다시 로그인해주세요"));
        if (refreshToken.isExpired()) {
            throw new UnauthorizedException("다시 로그인해주세요");
        }
        refreshTokenRepository.delete(refreshToken);

        User user = refreshToken.getUser();
        String newAccessToken = jwtUtil.create(user);
        String newRefreshToken = 발급(user);
        return new AuthResponse.ReissueDTO(newAccessToken, newRefreshToken);
    }

    @Transactional
    public void 폐기(String token) {
        refreshTokenRepository.findByToken(token).ifPresent(refreshTokenRepository::delete);
    }
}

import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

@RequiredArgsConstructor
@RestController
public class AuthController {

    private final RefreshTokenService refreshTokenService;

    @PostMapping("/reissue")
    public ResponseEntity<?> reissue(@Valid @RequestBody AuthRequest.RefreshDTO reqDTO) {
        AuthResponse.ReissueDTO reissueDTO = refreshTokenService.재발급(reqDTO.refreshToken());
        return ResponseEntity.ok()
                .header(JwtUtil.HEADER, reissueDTO.accessToken())
                .header(RefreshTokenService.HEADER, reissueDTO.refreshToken())
                .body(new Resp<>(200, "성공", null));
    }

    @PostMapping("/logout")
    public ResponseEntity<?> logout(@Valid @RequestBody AuthRequest.RefreshDTO reqDTO) {
        refreshTokenService.폐기(reqDTO.refreshToken());
        return Resp.ok(null);
    }
}

4.2 Security 기본 로그아웃 끄기

/logout 규칙만 열면 될 것 같지만, 그 전에 지금 상태에서 어떤 응답이 오는지 확인합니다. 예제 19-7까지 마친 상태에서 로그인해서 받은 리프레시 토큰을 본문에 넣어 POST http://localhost:8080/logout을 보내 봅니다. 기대한 {"status": 200, ...} 응답이 오지 않습니다. Postman 설정에서 자동 리다이렉트(Automatically follow redirects)를 끄고 다시 보내면 원인이 보입니다.

스프링 시큐리티는 기본으로 필터 체인 안에 로그아웃 필터(LogoutFilter)를 둡니다. 이 필터는 /logout 요청을 가로채 세션을 정리하고, 폼 로그인 화면 주소로 리다이렉트한 뒤 요청 처리를 끝냅니다. 요청이 필터 체인 안에서 끝나므로 주소 규칙 검사와 컨트롤러에 닿기 전에 응답이 나갑니다. 9장에서 CSRF 보호 · 폼 로그인 · HTTP Basic을 하나씩 껐습니다. 세션과 폼 로그인을 쓰지 않는 이 API에서는 기본 로그아웃 기능도 꺼야 같은 주소의 컨트롤러가 요청을 받습니다.

/logout은 /reissue와 같은 이유로 로그인 없이 열어 둡니다. 액세스 토큰이 만료된 사용자도 로그아웃은 할 수 있어야 합니다.

import com.newtenco.blog.core.filter.JwtAuthorizationFilter;
import com.newtenco.blog.core.util.JwtUtil;
import com.newtenco.blog.core.util.RespFilter;
import lombok.RequiredArgsConstructor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpMethod;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;
import org.springframework.web.cors.CorsConfiguration;
import org.springframework.web.cors.CorsConfigurationSource;
import org.springframework.web.cors.UrlBasedCorsConfigurationSource;

import java.util.List;

@RequiredArgsConstructor
@Configuration
public class SecurityConfig {

    private final JwtUtil jwtUtil;

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    @Bean
    public CorsConfigurationSource corsConfigurationSource() {
        CorsConfiguration config = new CorsConfiguration();
        config.setAllowedOrigins(List.of("http://localhost:5173"));
        config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE", "OPTIONS"));
        config.addAllowedHeader("*");
        config.setExposedHeaders(List.of("Authorization", "Refresh-Token"));

        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/**", config);
        return source;
    }

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http.headers(headers -> headers.frameOptions(frame -> frame.sameOrigin()));

        http.cors(cors -> cors.configurationSource(corsConfigurationSource()));

        http.csrf(csrf -> csrf.disable());
        http.formLogin(form -> form.disable());
        http.httpBasic(basic -> basic.disable());
        http.logout(logout -> logout.disable());

        http.sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS));

        http.addFilterBefore(new JwtAuthorizationFilter(jwtUtil), UsernamePasswordAuthenticationFilter.class);

        http.exceptionHandling(ex -> ex
                .authenticationEntryPoint((req, res, e) -> RespFilter.fail(res, 401, "로그인 후 이용해주세요"))
                .accessDeniedHandler((req, res, e) -> RespFilter.fail(res, 403, "권한이 없습니다")));

        http.authorizeHttpRequests(auth -> auth
                .requestMatchers(HttpMethod.OPTIONS, "/**").permitAll()
                .requestMatchers("/join", "/login", "/check-username").permitAll()
                .requestMatchers(HttpMethod.POST, "/reissue", "/logout").permitAll()
                .requestMatchers("/h2-console/**").permitAll()
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .requestMatchers(HttpMethod.GET, "/api/boards/**").permitAll()
                .requestMatchers("/api/**").hasAnyRole("USER", "ADMIN")
                .anyRequest().denyAll()
        );

        return http.build();
    }
}

4.3 로그아웃 뒤에 남는 액세스 토큰

로그아웃으로 지운 것은 리프레시 토큰뿐입니다. 로그아웃 전에 받은 액세스 토큰을 여전히 쓸 수 있는지 확인합니다. 4.2의 순서대로 로그아웃한 다음, 로그인 때 받은 Authorization 값을 헤더에 그대로 넣어 GET http://localhost:8080/api/users/me를 보냅니다.

실행 결과

JSON

  "status": 200,
  "msg": "성공",
  "body": {

로그아웃했는데도 내 정보가 조회됩니다. 1.1에서 말한 액세스 토큰의 성질 때문입니다. 인증 필터는 서명과 만료 시간만 보고 DB를 조회하지 않습니다. 그래서 서버는 이 토큰이 로그아웃한 사용자의 것인지 알 방법이 없습니다. 이 토큰은 JwtUtil의 만료 시간이 지날 때까지 유효하고, 이 책의 설정값으로는 최대 하루입니다.

이 빈틈은 다음 방법으로 줄입니다.

방법하는 일대가
액세스 토큰 만료 시간 줄이기남은 토큰이 유효한 시간을 몇 분~몇십 분으로 줄인다재발급 요청이 늘어난다
클라이언트에서 토큰 지우기로그아웃할 때 저장해 둔 두 토큰을 모두 버린다이미 새어 나간 토큰은 막지 못한다
차단 목록(denylist)로그아웃한 액세스 토큰을 만료될 때까지 서버에 기록하고 필터에서 검사한다요청마다 저장소를 조회해야 해서 토큰 방식의 장점이 줄어든다

리프레시 토큰을 도입한 목적은 첫 번째 방법을 쓸 수 있게 하는 데 있습니다. 액세스 토큰이 짧게 만료돼도 사용자는 재발급으로 로그인 상태를 이어 갈 수 있기 때문입니다. 이 책은 실습 중에 토큰이 자주 만료되지 않도록 액세스 토큰의 만료 시간을 하루로 둡니다. JwtUtil은 만료 시간을 설정값으로 받으므로, 실제 서비스에서는 코드를 고치지 않고 설정 파일의 값만 짧게 줄이면 됩니다. 클라이언트도 로그아웃할 때 두 토큰을 모두 지워야 합니다. 차단 목록은 이 책에서 구현하지 않습니다.
