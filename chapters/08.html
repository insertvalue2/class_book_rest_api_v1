8장. 페이징이란?

1. 페이징의 개념

1.1 목록은 왜 나눠서 줄까?

7장까지 만든 글 목록 API는 board_tb에 있는 글을 한 번에 전부 돌려줍니다. 지금은 샘플 데이터가 5개뿐이라 문제가 드러나지 않습니다. 글이 만 개로 늘면 요청 한 번마다 글 만 개를 조회해 DTO로 바꾸고, 그 JSON을 모두 네트워크로 보내야 합니다. 화면에 한 번에 보이는 글은 열 개 남짓이므로 나머지는 쓰이지 않는 데이터입니다.

페이징(paging)은 목록을 정해진 개수씩 쪽(page)으로 나누고, 요청받은 쪽의 데이터만 조회해 돌려주는 방법입니다. 클라이언트가 0번 쪽을 요청하면 서버는 그 쪽에 들어갈 글만 데이터베이스에서 꺼냅니다. 그러면 데이터베이스에서 가져오는 행 수와 서버가 만드는 객체 수, 응답 크기가 모두 쪽 크기만큼으로 줄어듭니다.

이 장에서는 그림 8-1처럼 최신 글이 먼저 오도록 글 번호 내림차순으로 정렬한 뒤 3개씩 자릅니다. 쪽 번호는 0부터 세므로 첫 쪽은 0번 쪽입니다. 데이터베이스는 이런 요청을 SQL의 limit · offset 구문으로 처리합니다. H2에서는 offset ... rows fetch first ... rows only 꼴로 씁니다. Spring Data JPA로 페이징하면 이 SQL을 개발자가 직접 쓰지 않아도 됩니다.

1.2 Pageable과 PageRequest

Spring Data JPA는 페이징 요청을 Pageable 인터페이스로 나타냅니다. Pageable에는 쪽 번호(몇 번 쪽인지), 쪽 크기(한 쪽에 몇 개인지), 정렬 조건(어떤 순서로 늘어놓는지)이 들어 있습니다. Repository 메서드가 매개변수로 Pageable을 받으면 Spring Data JPA가 이 정보를 읽어 쿼리에 쪽 나누기와 정렬을 덧붙입니다.

Pageable은 인터페이스이므로 실제 객체는 구현 클래스인 PageRequest로 만듭니다. 객체는 생성자가 아니라 정적 메서드 PageRequest.of()로 만듭니다.

기본 문법

Pageable pageable = PageRequest.of(쪽번호, 쪽크기, 정렬);
매개변수뜻이 장에서 쓰는 값

2. 목록 나누기

2.1 Page 반환과 countQuery

Pageable을 받는 Repository 메서드는 반환 타입을 List 대신 Page로 둘 수 있습니다. Page는 요청한 쪽의 데이터에 전체 데이터 개수와 전체 쪽 수 같은 정보를 더한 객체입니다. 전체 쪽 수를 계산하려면 전체 개수가 필요합니다. 그래서 Page를 반환하는 메서드는 쪽 데이터를 가져오는 쿼리를 실행한 뒤, 개수를 세는 count 쿼리를 한 번 더 실행합니다.

@Query로 JPQL을 직접 쓰면 Spring Data JPA는 그 JPQL을 고쳐서 count 쿼리를 스스로 만들려고 합니다. 그런데 6장에서 쓴 글 목록 쿼리에는 join fetch b.user가 들어 있습니다. 개수만 세는 쿼리는 엔티티를 가져오지 않으므로 fetch join이 필요 없습니다. 자동으로 만든 count 쿼리는 원래 쿼리 모양을 따라가므로, 이 책의 버전에서는 fetch만 떼고 user_tb와의 join은 그대로 남깁니다. 글 개수는 board_tb만 세면 되므로 이 join은 필요 없습니다. 또 쿼리가 복잡해지면 자동 변환이 실패하는 경우도 있습니다. 그래서 @Query의 countQuery 속성에 개수를 세는 쿼리를 직접 적어 둡니다. 어떤 SQL로 개수를 세는지 코드에 드러나는 장점도 있습니다.

기본 문법

Java
1 2 3
@Query(value = "데이터를 가져오는 JPQL",
        countQuery = "개수를 세는 JPQL")
Page<엔티티타입> 메서드명(Pageable pageable);

글 목록 JPQL의 order by b.id desc도 지웁니다. 이제 정렬은 Pageable에 담아서 넘깁니다. JPQL에도 정렬을 남겨 두면 정렬 조건을 두 군데에서 관리하게 됩니다.

package com.newtenco.blog.board;

import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;

import java.util.Optional;

public interface BoardRepository extends JpaRepository<Board, Integer> {

    @Query(value = "select b from Board b join fetch b.user",
            countQuery = "select count(b) from Board b")
    Page<Board> findAllJoinUser(Pageable pageable);

    @Query("select b from Board b join fetch b.user where b.id = :id")
    Optional<Board> findByIdJoinUser(@Param("id") Integer id);
}

package com.newtenco.blog.board;

import com.newtenco.blog.core.handler.errors.NotFoundException;
import lombok.RequiredArgsConstructor;
import org.springframework.data.domain.PageRequest;
import org.springframework.data.domain.Pageable;
import org.springframework.data.domain.Sort;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.List;

@RequiredArgsConstructor
@Transactional(readOnly = true)
@Service
public class BoardService {

    private final BoardRepository boardRepository;

    public List<BoardResponse.ListDTO> 글목록(Integer page) {
        Pageable pageable = PageRequest.of(page, 3, Sort.by(Sort.Direction.DESC, "id"));
        return boardRepository.findAllJoinUser(pageable).getContent().stream()
                .map(BoardResponse.ListDTO::new)
                .toList();
    }

    public BoardResponse.DetailDTO 글상세(Integer id) {
        Board board = boardRepository.findByIdJoinUser(id)
                .orElseThrow(() -> new NotFoundException("게시글을 찾을 수 없습니다"));
        return new BoardResponse.DetailDTO(board);
    }
}

서버를 실행한 PowerShell 창의 SQL 로그를 보면 쿼리가 두 번 실행됩니다. 첫 번째 쿼리는 board_tb와 user_tb를 조인하고 order by와 fetch first ? rows only를 붙였습니다. 두 번째 쿼리는 countQuery에 적은 count 쿼리입니다.

count 쿼리가 늘 실행되지는 않습니다. 가져온 데이터가 한 개 이상이면서 쪽 크기보다 적으면 그 쪽이 마지막 쪽이므로, 앞쪽 개수에 이번 쪽 개수를 더해 전체 개수를 알 수 있습니다. 첫 쪽에서 쪽 크기보다 적게 가져온 경우도 그 개수가 곧 전체 개수입니다. 이럴 때 Spring Data JPA는 count 쿼리를 건너뜁니다. 예제 8-1에서 ?page=1을 보내면 글 2개가 오고 count 쿼리는 실행되지 않습니다. 반대로 범위를 벗어난 쪽을 요청해 빈 목록이 오면 전체 개수를 알 수 없으므로 count 쿼리를 실행합니다.

2.2 정렬(Sort)

Sort는 정렬 조건을 담는 객체입니다. Sort.by()에 정렬 방향과 기준 필드 이름을 넘겨서 만듭니다. 예제 8-1의 Sort.by(Sort.Direction.DESC, "id")는 id 필드 기준 내림차순이므로 번호가 큰 최신 글이 먼저 옵니다.

2.3 @RequestParam과 기본값

몇 번 쪽을 받을지는 클라이언트가 정합니다. 쪽 번호는 자원을 가리키는 값이 아니라 조회 조건을 덧붙이는 값입니다. 이런 값은 주소 경로가 아니라 쿼리 문자열(query string)로 받습니다. 쿼리 문자열은 주소 뒤의 ? 다음에 이름=값 꼴로 붙는 부분입니다(/api/boards?page=1). 값이 여러 개면 &로 이어 붙입니다.

@RequestParam은 쿼리 문자열의 값을 컨트롤러 메서드의 매개변수로 받아 줍니다. 7장의 @PathVariable은 주소 경로에서 바뀌는 자리의 값을 꺼냈고, @RequestParam은 ? 뒤에서 값을 꺼냅니다.

기본 문법

Java
1
@RequestParam(value = "파라미터이름", defaultValue = "기본값") 타입 변수명

@RequestParam으로 받는 값은 기본적으로 꼭 있어야 합니다. defaultValue가 없는데 page 없이 /api/boards로 요청하면 400 오류가 납니다. 예제 8-1처럼 defaultValue = "0"을 주면 값이 없을 때 문자열 "0"을 쓰고, 스프링이 이 문자열을 Integer 0으로 바꿔 넣습니다. 그래서 page를 빼고 요청하면 첫 쪽이 옵니다.

3. 쪽 정보 응답

3.1 Page가 알려 주는 정보

Page 객체에는 쪽 데이터와 함께 쪽을 나눈 결과도 들어 있습니다. 자주 쓰는 메서드는 다음과 같습니다. 오른쪽 열은 글 5개를 3개씩 나누고 0번 쪽을 요청했을 때의 값입니다.

메서드돌려주는 값0번 쪽의 값
getContent()이 쪽의 데이터 목록글 5 · 4 · 3
getNumber()현재 쪽 번호(0부터)0
getSize()쪽 크기3
getTotalElements()전체 데이터 개수5
getTotalPages()전체 쪽 수2
isFirst()첫 쪽인지true
isLast()마지막 쪽인지false
hasNext()다음 쪽이 있는지true

전체 쪽 수는 전체 개수를 쪽 크기로 나눈 뒤 올림해서 구합니다. 5를 3으로 나누면 1.67이므로 2쪽입니다. 화면에서는 이 값으로 버튼 상태를 정합니다. 예를 들어 isFirst가 true면 이전 버튼을 끄고, isLast가 true면 다음 버튼을 끕니다.

3.2 PageDTO 만들기

컨트롤러에서 Page<Board>를 그대로 응답하면 안 됩니다. Page<Board> 안에는 엔티티가 그대로 들어 있으므로, 6장에서 엔티티를 그대로 내보내지 않은 이유가 여기에도 똑같이 해당합니다. 또 Page 구현 객체를 그대로 JSON으로 바꾸면 정렬 객체 같은 내부 정보까지 함께 나갑니다. Spring Data도 이 방식을 권하지 않아서, 그렇게 내보내면 경고 로그를 남깁니다.

그래서 화면에 필요한 값만 골라 record DTO를 하나 더 만듭니다. 글 목록은 이미 있는 ListDTO로 바꾸고, 쪽 정보로는 현재 쪽 번호 · 전체 쪽 수 · 첫 쪽 여부 · 마지막 쪽 여부만 담습니다. ListDTO에는 엔티티를 받는 보조 생성자가 있습니다. PageDTO에도 Page<Board>를 받는 보조 생성자를 두면 Service에서 DTO를 한 줄로 만들 수 있습니다.

package com.newtenco.blog.board;

import org.springframework.data.domain.Page;

import java.sql.Timestamp;
import java.util.List;

public class BoardResponse {

    public record ListDTO(Integer id, String title, String content, String username, Timestamp createdAt) {

        public ListDTO(Board board) {
            this(board.getId(), board.getTitle(), board.getContent(), board.getUser().getUsername(), board.getCreatedAt());
        }
    }

    public record PageDTO(List<ListDTO> boards, int number, int totalPage, boolean isFirst, boolean isLast) {

        public PageDTO(Page<Board> boardPage) {
            this(boardPage.getContent().stream().map(ListDTO::new).toList(),
                    boardPage.getNumber(),
                    boardPage.getTotalPages(),
                    boardPage.isFirst(),
                    boardPage.isLast());
        }
    }

    public record DetailDTO(Integer id, String title, String content, Integer userId, String username) {

        public DetailDTO(Board board) {
            this(board.getId(), board.getTitle(), board.getContent(), board.getUser().getId(), board.getUser().getUsername());
        }
    }
}

4. 제목 검색

4.1 like와 concat

제목에 특정 글자가 들어간 글만 찾을 때는 SQL처럼 JPQL에서도 like를 씁니다. %는 글자가 몇 개든 상관없다는 뜻입니다. 앞뒤에 %를 붙인 '%제목%'은 "제목"이 어디에 들어 있든 맞는 조건입니다.

검색어는 요청마다 다르므로 7장처럼 이름 있는 파라미터 :keyword로 받습니다. 이때 '%:keyword%'처럼 따옴표 안에 파라미터를 쓰면 안 됩니다. 따옴표 안은 전부 문자열 값이라서 :keyword가 파라미터로 읽히지 않고, 글자 그대로 ":keyword"를 찾는 조건이 됩니다. 그래서 JPQL 함수 concat으로 %와 파라미터 값을 이어 붙입니다.

기본 문법

SQL
1
where 별칭.필드명 like concat('%', :파라미터이름, '%')

검색어가 "1"이면 조건은 like '%1%'과 같습니다. 검색어가 빈 문자열 ""이면 like '%%'가 되어 모든 제목과 맞습니다. 검색어 없이 보낸 요청이 전체 목록을 받는 것은 이 때문입니다.

검색 조건을 넣을 때는 countQuery에도 똑같은 where 조건을 넣어야 합니다. 데이터 쿼리는 검색 결과만 가져오는데 count 쿼리가 전체 글을 세면 쪽 정보가 틀립니다. 검색 결과는 1개인데 전체 쪽 수가 2로 나오는 식입니다.

4.2 검색과 페이징 함께 쓰기

Repository 메서드는 keyword와 Pageable을 함께 받습니다. @Param("keyword")는 JPQL의 :keyword 자리에 값을 넣고, Pageable은 앞에서처럼 정렬과 쪽 나누기를 붙입니다. 컨트롤러도 keyword를 @RequestParam으로 받고, 기본값은 빈 문자열로 둡니다.

package com.newtenco.blog.board;

import org.springframework.data.domain.Page;
import org.springframework.data.domain.Pageable;
import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;

import java.util.Optional;

public interface BoardRepository extends JpaRepository<Board, Integer> {

    @Query(value = "select b from Board b join fetch b.user where b.title like concat('%', :keyword, '%')",
            countQuery = "select count(b) from Board b where b.title like concat('%', :keyword, '%')")
    Page<Board> findAllJoinUser(@Param("keyword") String keyword, Pageable pageable);

    @Query("select b from Board b join fetch b.user where b.id = :id")
    Optional<Board> findByIdJoinUser(@Param("id") Integer id);
}
